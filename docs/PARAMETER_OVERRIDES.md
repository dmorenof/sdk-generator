# Parameter inheritance and overrides (v0.26.1)

For supported Swagger 2.0 and OpenAPI 3.0/3.1 parameter schemas, identity is the exact pair `(in, name)`. A declaration on an operation replaces the complete declaration at the Path Item level. Fields are not merged: omitted styles return to their normal defaults and old types, constraints and required flags do not leak into the replacement. Names in different locations remain independent.

An absent operation parameter list or `parameters: []` retains Path Item declarations. Operations cannot remove inherited parameters by clearing their own list. Local reusable Parameter references are resolved before identity comparison. Existing reference sibling and alias rules still apply. Reusable component maps can contain distinct declarations with the same identity; this is legal until both are used in one parameter list.

Duplicate identities inside one Path Item list or inside one operation list are invalid. Previous compatibility normalization silently kept the last declaration; v0.26.1 rejects this in normal and strict generation. An operation override cannot hide an invalid duplicate in the parent list. Inspection reports `duplicate_parameter` at the repeated usage, with the source JSON Pointer, operation where applicable and reference chain. Referenced Path Item origins and escaped pointer tokens are retained. Non-list declarations report `invalid_parameter_list`.

The existing normalizer and auditor implement these checks; no runtime or transport layer is added. Generated GetParams/PostParams continue to use effective types and validation. Tests use an inherited string list replaced by a GET integer list and a POST scalar, different path styles, inherited cookies, a header with the same name as a query, and a query named body alongside a JSON payload. Mutations fail before HTTP. An installed SDK checks real GET/POST targets, headers, cookies and body bytes; published-package smoke also verifies duplicate rejection.

See the [OpenAPI Parameter Object](https://spec.openapis.org/oas/v3.1.2.html#parameter-object) and [Swagger 2.0 Path Item](https://spec.openapis.org/oas/v2.0.html#path-item-object). This does not extend the supported schema/style subset, implement default-value injection or complete general document validation. Existing unsupported shapes retain their diagnostics. The stable runtime minimum remains ^0.20.0.
