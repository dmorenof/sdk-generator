The GitHub Action fetches the official JSON, verifies its digest, and archives the source and the JSON report as artifacts. If the upstream specification changes, it reports SPECIFICATION DRIFT; a changed document must not silently replace the pinned input.

## Report meaning

Each operation is attempted with its transitive referenced schema closure so an unrelated model failure will not conceal it. The full original source is also parsed and generated without any changes.

- `generated`: the normalizer and PHP emitter accepted the isolated operation (not yet a runtime HTTP guarantee).
- `normalization_failed`: parsing/schema validation rejected the operation.
- `generation_failed`: interpretation succeeded but PHP source generation failed.
- `selection_failed`: a diagnostic slice could not be assembled.
- `full.status`: result of the untouched entire contract.
- `accepted: true`: requires every operation AND the full original contract to generate successfully.

The CLI exits nonzero and the dedicated workflow stays red until the complete pinned specification works. Separate regular CI tracks previously supported behavior and should remain independent of the acceptance gate. We will fix common classes of unsupported OpenAPI constructs, not add Casafari-specific patches.

Once source generation passes, acceptance must be extended to execution: PHP syntax, typed DTOs, request/response handling, authorization and errors, with mock transports.
