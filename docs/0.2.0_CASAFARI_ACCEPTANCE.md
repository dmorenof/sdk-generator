## Re-run after schema and directional DTO support

- The normalizer/emitter support bounded `allOf`, `anyOf`, and `oneOf` composition, with shared generated `Core\\AnyOf` and `Core\\OneOf` behavior.
- `default` is preserved as metadata, `readOnly`/`writeOnly` are handled by request/response direction, `pattern` is validated with PCRE, and type-less schemas can be represented as `mixed`.
- Before security generation was added, the latest local run was `normalization_failed` at `Unsupported operation security at get /alerts-api/feeds`; isolated generation was **0 / 46**. The fixture declares HTTPBearer and PlatformApiKey, both as HTTP bearer schemes.
- Security is now modeled and emitted for HTTP bearer, HTTP basic, and header/query API keys. `$ref` title/description annotations and JSON-suffix media types such as `application/problem+json` are also supported.
- HTTP parameter enums now use their primitive PHP type and are validated against their declared values; nullable primitive `anyOf` parameters remain supported.
- Inline success schemas now generate deterministic operation-derived DTOs/collections, and inline object error schemas generate typed response DTOs. A single body-bearing success response may also declare no-content success statuses; the method returns the generated response type or `null`.
- Latest pinned local run: **46 / 46** isolated operations generated; full source generation also succeeds. All **1,189** generated files pass PHP syntax checks. Runtime behavior across the full API is not yet verified.
- A Docker-backed runtime smoke test now generates the SDK from the pinned fixture and exercises authenticated `GET` and `POST /api/v1/listing-alerts/feeds` calls with mock HTTP. It verifies query and JSON body serialization, bearer credentials, nested DTO/enum/collection hydration, typed inline `401` errors, and refusal to send without credentials.
- Credentials are caller-supplied and are never embedded in generated code. Authentication is no longer the compatibility blocker.

**Next:** extend acceptance to runtime execution of typed DTOs, request/response handling, authorization and errors with mock transports. Do not add provider-specific exceptions.
## Report meaning

Each operation is attempted with its transitive referenced schema closure so an unrelated model failure will not conceal it. The full original source is also parsed and generated without any changes.

- `generated`: the normalizer and PHP emitter accepted the isolated operation (not yet a runtime HTTP guarantee).
- `normalization_failed`: parsing/schema validation rejected the operation.
- `generation_failed`: interpretation succeeded but PHP source generation failed.
- `selection_failed`: a diagnostic slice could not be assembled.
- `full.status`: result of the untouched entire contract.
- `accepted: true`: requires every operation AND the full original contract to generate successfully.

The CLI exits nonzero unless every operation and the entire source generate successfully; that source-generation gate now passes for the pinned input. Separate regular CI tracks previously supported behavior and should remain independent of the acceptance gate. We will fix common classes of unsupported OpenAPI constructs, not add Casafari-specific patches.

Source generation and PHP syntax passing are not full runtime acceptance. The smoke test covers representative paths only; broader operation coverage and full-spec execution checks with mock transports remain.
