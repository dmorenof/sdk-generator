# SDK Generator 0.2.0 — Casafari CRM v1 contract gap audit

**Source inspected:** `dmorenof/casafari-sdk@master:src/Core/v1.json` (Swagger 2.0, public repository), checked on 2026-10-20. This is a factual inspection, **not** evidence that the full Casafari SDK can already be regenerated. Casafari's existing handwritten/generated classes and tests remain the functional reference.

## Contract characteristics

- **14 paths / 14 operations**, covering Agency, CasafariGo, CodeTable, Entity, Leads, Property.
- **82 schema definitions**, **891 declared properties**, **104 array properties**, **23 enum properties**, **5 `readOnly` properties**, **1 dictionary/`additionalProperties` properties**.
- **82 schema identifiers** are not directly valid PHP class names (e.g. `Casafari.Crm.Api.Dtos.Agency.AgencyDto`). **0 property names** also need wire-name mapping.
- CodeTable GET declares **10 dotted query parameters** (`rq.lang`, `rq.includeBusinessTypes`, etc.). These must map to readable, typed PHP request fields while preserving their exact wire names.
- Many object properties are nested references; arrays may hold DTOs and enums. Responses include Casafari-specific `Success`/`Errors` conventions that belong to those generated schema classes, not every SDK's universal `Core\Response`.

## Verified gaps between 0.2.0 draft and complete Casafari generation

1. **Hierarchical schema paths — implemented:** dotted identifiers are mapped to complete PSR-4 paths, e.g. `Casafari.Crm.Api.Dtos.Agency.AgencyDto` → `src/Casafari/Crm/Api/Dtos/Agency/AgencyDto.php`. No common prefix is removed; collision checks remain. The API's SDK root namespace is separate from schema hierarchy.
2. **Query-field name mapping**: `rq.*` names are invalid PHP identifiers; do not silently strip the prefix or change on-the-wire meaning. Request objects must retain wire-to-property metadata.
3. **Schema keywords**: `readOnly` fields and dictionary `additionalProperties` require explicit handling; the current subset can reject them. Date-time formats need their own documented validation policy.
4. **Casafari API grouping and naming**: current generated `ApiClient` is one facade; Casafari provides separate AgencyApi, PropertyApi, LeadApi, etc. OperationIds like `Agency_GetAgencies` should map predictably to ergonomic methods, without losing identity/colliding.
5. **Typed Request/Response outputs**: root role inference and typed path/query request objects now work for synthetic APIs. Named Casafari-style request and response namespaces, shared schemas used in both roles, and exact transport/error policy still need acceptance tests against Casafari operations.
6. **Behavioral equivalence**: convert representative existing Casafari tests to generator acceptance tests (typed nested Lead/Agency DTOs, POST requests, GET CodeTable query names, middleware, response error behavior), then increase fixture breadth until the full 14-path contract can be generated. Do not treat passing synthetic Accounts/Catalog tests as full parity.

## Required guardrails

- The main `sdk-generator` 0.1.0 release remains unchanged; this is development for 0.2.0 in PR #13.
- No dependency on separate `sdk-runtime`. The Core is emitted once inside every generated SDK.
- Do not copy hardcoded Casafari host allowlists or `Success` policy into unrelated SDKs.
- Preserve the existing API-specific typed array library semantics.
- Never infer the API's root namespace from its schema prefixes or silently remove repeated path segments. Optional root namespace naming uses `info.title`; users may override it explicitly. The old Casafari Swagger title is `External Api Version`, which does not provide a meaningful Casafari SDK name — leave it to an explicit override rather than infer from `Casafari.Crm.Api`.
- Preserve all dotted schema path components and case-insensitive collision detection. Reject invalid segments instead of silently correcting source definitions.
- Treat `benchmark/FINDINGS.md` as a **v0.1.0 historical benchmark**. New object-based signatures require freshly verified apples-to-apples comparisons before performance claims.

## Suggested sequence

**Next:** map dotted query names such as `rq.lang` to typed PHP fields and preserve exact HTTP wire keys, without inventing Casafari-specific rules; then cover other unsupported schema keywords, real-world fixture generation and end-to-end behavior.

Do not prematurely mark the 0.2.0 release ready while these gaps remain.
